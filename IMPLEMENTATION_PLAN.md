## Этапы и критерии приёмки

| Приоритет | Работа | Критерий приёмки |
| --- | --- | --- |
| P0 | Проверка исполнимости при отправке и rejudge. Завершение ранее зависших посылок. Отображение доступности отправки в UI. | Диагностический Polygon и Lua без подключённого исполнения получают HTTP 409. Очередь принимает готовый Standard, а старые неисполняемые попытки получают `testing_error`. |

| P1 | Подключить изолированный Grader, автоматический и ручной запуск, ограниченное чтение снимка, логи и UI preview/publish. | Worker получает данные в пределах снимка. Предпросмотр сохраняет текущие опубликованные оценки. Публикация атомарно переключает таблицу. |

## Решения по мере реализации

- Для очереди, параллелизма и восстановления зафиксировать действующее поведение. Согласовать продуктовые изменения там, где ТЗ оставляет открытые вопросы.
- Для импорта и рендеринга обновить матрицу совместимости. Описать поддерживаемые возможности Polygon, языки и подмножество LaTeX.
- До включения автоматического Grader определить область расчёта, видимость чужих посылок и трактовку отсутствующих оценок.

## Выполнено

- P0. Приём посылок, rejudge, выдача данных страницы задачи и отбор заданий используют одну проверку исполнимости ревизии. В текущей интеграции исполняются опубликованные Standard v1 с готовым `ustar_v1`-пакетом. Диагностические задачи и опубликованные пакеты Lua доступны для просмотра.
- P0. Worker завершает ранее созданные неисполняемые попытки в статусах `waiting` и `queued` с результатом `testing_error`. Интеграционный тест на PostgreSQL проверяет отказ для Polygon и Lua, закрытие старой попытки и сохранение готовой Standard-попытки в очереди.
- P0. Менеджер контеста может просмотреть посылки задачи, скачать диагностику и отменить попытку в статусе `waiting` или `queued`. Повторная отмена идемпотентна. Отмена и выдача аренды блокируют одну строку попытки, поэтому опубликованное до отмены задание уже нельзя забрать.
- P0. Standard Invoker отправляет события запуска, сборки и начала теста через существующий журнал с сохранением последовательности при перезапуске. У Standard тесты последовательны, поэтому интерфейс показывает последний начатый тест. Результаты отдельных тестов публикуются при завершении проверки. После применения frontend-политики REST и SSE показывают прогресс только менеджерам. Контракт обновлён в `openapi/openapi.yaml`.
- P0. Сквозной тест с PostgreSQL, HTTPS MinIO, JetStream, mTLS и rootless Podman проверяет отображение начатого теста до завершения проверки, порядок событий Standard, повтор события прогресса и финального события после потери ACK, а также замену попытки после истечения аренды.
- P0. Активную попытку Standard можно отменить из интерфейса. Invoker получает запрос при продлении аренды, останавливает выполнение, очищает ресурсы Podman и отправляет `RUN_CANCELLED` через журнал. Сквозной тест проверяет исчезновение работающего контейнера до подтверждения, а также повтор события после потери ACK.
- P0. Запрос отмены прекращает продление аренды. Если аренда истекает, Backend завершает попытку без повторной постановки. Если Invoker уже начал публиковать результат, результат может успеть зафиксироваться до истечения аренды. При истечении аренды без подтверждения очистку ресурсов отслеживает журнал Invoker.

- P0. Lua API v1 для `posix_sh` исполняется отдельным durable consumer через общий протокол аренды и журнал. `TestLuaSubmissionExecution` подтвердил публикацию, отправку, вердикт, runner log и удаление активного контейнера до подтверждения отмены. `TestStandardSubmissionExecution` и `zig build test-lua-runner -Dlua-runner=true` также прошли.
- P1. В интерфейсе добавлены управление ролями и участниками, настройки и лимиты, переключение закреплённой ревизии, rejudge, авторинг Standard/Lua через ZIP, редактирование языков, история материалов и вложения закреплённых ревизий. Smoke-тесты на Dex/OpenFGA подтвердили выдачу ролей, публикацию без смены закреплённой ревизии, её явную смену, rejudge на текущей ревизии, историю посылки и скачивание вложения.
- P1. Тесты и ресурсы в UTF-8 до 256 КиБ можно добавлять, редактировать и удалять по отдельности в черновиках Standard и Lua. Для бинарных ресурсов доступен ZIP. HTTP smoke проверил чтение, удаление `runner.lua`, отказ в валидации без него, восстановление файла и неизменяемость опубликованной ревизии. Сквозной тест Standard успешно исполнил пакет с изменёнными входом и ответом.
- P1. Grader выполняет встроенный Python-агрегатор в rootless Podman без сети. `TestWorkerPublication` проверяет автоматический и ручной preview, область снимка, неверный токен, сохранение лога, атомарную публикацию и истечение аренды. Политика максимума базового балла и нуля при отсутствии оценок не согласована как продуктовый стандарт.
- P1. Пользовательский `grader.py` хранится отдельно от пакета Invoker и закрепляется в опубликованной ревизии. Внутренний API по capability выдаёт список результатов снимка с языками, вердиктами и базовыми баллами. Python-runtime получает те же ограниченные данные через stdin от worker, не имеет сети и не получает токен или доступ к БД. `deploy/smoke-grader.py` и headless Chrome проверили выполнение скрипта, изоляцию preview, явную публикацию и оценку `0.75` в scoreboard. Шаблон host-сервиса — `deploy/podtest-grader.service`.
- P1. Синхронизированы публичные маршруты OpenAPI; тест двусторонней проверки маршрутов запускается в CI. REST/SSE и браузерная проверка frontend описаны в `IMPLEMENTATION_PLAN_FRONTEND.md`.
- P1. Отдельно прошёл `TestS3SignedArtifact` на одноразовом HTTPS MinIO.
- P2. Backend и Nginx собраны по Dockerfile из чистой копии дерева с npm offline-кэшем; на отдельном Compose-проекте успешно прошёл `PODTEST_SKIP_BUILD=1 sh deploy/up.sh --dev -p podtest-clean`, включая миграции, readiness и authoring smoke. Скрипт дожидается готовности PostgreSQL перед миграциями. На dev проверены приватность портов (только Nginx на loopback), перезапуск API/worker и повторное чтение исходника. `pg_dump`/`pg_restore` проверены на отдельной БД; сравнивались записи посылок, тестов, материалов и артефактов.
- P2. Тома PostgreSQL, MinIO, OpenFGA и NATS восстановлены в отдельном dev-проекте. С прежним URL OIDC issuer владелец и менеджер получили исходник, а посторонний пользователь получил `403`. Для OpenFGA восстановили права записи на корень тома SQLite. В отдельном прогоне восстановили том JetStream с 48 опубликованными заданиями: durable consumer сохранил очередь, один Standard Invoker принял и подтвердил все 48 за 1 м 39 с, без оставшихся сообщений или повторных попыток. Это тест восстановления и обработки очереди, не оценка production-пропускной способности.

## Границы приёмки и решения для production

- Не проверялись реальный production OIDC/TLS, размещение execution-узлов и пропускная способность на целевой инфраструктуре. Онлайн-сборка зависела от npm-реестра, который на тестовом хосте возвращал таймауты; сборка и развёртывание проверены раздельно.
- Grader ограничен одной задачей контеста и её снимком. Доступ к исходникам и ресурсам из скрипта не предусмотрен. Межзадачный расчёт и продуктовую политику отсутствующих оценок нужно согласовать отдельно. Lua за пределами shell API v1 не заявлен.
