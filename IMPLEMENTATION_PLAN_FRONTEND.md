# Требования Frontend

1) Вынести интерфейс создания в одну вкладку, чтобы кнопки создания не мешали участнику

2) Добавить менеджеру контеста возможность просматривать полный протокол, а участнику - только вердикты по всем тестам

3) Добавить возможность менеджеру смотреть код всех участников

4) Добавить возможность участнику видеть свой код

5) Добавить базовый редактор кода для отправки задач, чтобы не обязательно было прикреплять код файлом

## Реализация и проверка

- Создание курсов, контестов и задач перенесено из каталогов в **Workspace**. Настройки и редактирование существующих ресурсов остались на их страницах.
- Менеджер видит протокол с ревизией, временем, баллами, группами, метаданными и диагностическими вложениями, если они есть. В режиме `tests` участник получает только идентификаторы и вердикты тестов, в `summary` — итог, в `hidden` — ни того, ни другого. REST и SSE используют один фильтр.
- Исходник отображается как текст и доступен для скачивания только владельцу или менеджеру контеста. Менеджер может пролистать список посылок задачи. Код из редактора и файл проходят один и тот же endpoint и лимит 256 КиБ.
- `deploy/smoke-submissions.py`: прошёл с тремя Dex-аккаунтами, включая отказ постороннему, выдачу роли без раскрытия чужого исходника и совпадение REST/SSE для всех режимов. Проверка в headless Chrome: участник отправил код из редактора, открыл свой исходник и увидел только вердикты; менеджер открыл исходник участника и полный протокол; в каталоге удалена кнопка создания, форма доступна в Workspace.
- Приёмка: 5 из 5 требований выполнены. Production-сборка Vue и повторный smoke REST/SSE прошли. Дополнительно в headless Chrome проверены предпросмотр и публикация Grader, scoreboard и сброс редактора пакета при смене ревизии.
